* Handle recursive build dependencies.

  `page.html.temple` includes navigation:

  ```
  <nav>
  <ol>
    <li><a href="{{resource.html.index.url}}">Home</a>
    <li><a href="{{resource.html.about.url}}">About</a>
    <li><a href="{{resource.html.resources.url}}">Resources</a>
  </ol>
  </nav>
  ```

  Which means that transitively, `article.html.temple` depends on specific html
  resources. But we already have `html:article-{name}` depending on
  `article.html.temple` via the article rendering rule. This seems fraught.
  Maybe the dependency graph is still acyclic because `article-render`'s
  outputs don't overlap with `page.html.temple`'s inputs.

  Another loop is that the `index`, `about`, and `resources` will be compiled
  to `html` using some other render rule that involves `page.html.temple`.
  So the resulting html depends on `page.html.temple`, and `page.html.temple`
  also depends on the html.

  I could break the cycle by adding a `page` resource that has `url` in its
  metadata and reference that instead:

  ```
  <nav>
  <ol>
    <li><a href="{{resource.page.index.metadata.url}}">Home</a>
    <li><a href="{{resource.page.about.metadata.url}}">About</a>
    <li><a href="{{resource.page.resources.metadata.url}}">Resources</a>
  </ol>
  </nav>
  ```

  Then the page render rule ensures that the generated html has that URL.

  If I keep managing to break cycles, then it should be an error to construct
  cyclic rules.
